# Native scene review inventory

Status: preparation for [ticket 23](https://github.com/dvcol/planner/issues/23), based on production source at `7286a0db`. No scene receives final visual or accessibility acceptance from this inventory. Existing reports retain their own source epochs and executed results.

## Context and goal

The saved application now has native creation, capture, ordered plans, calendars, recovery and association Undo. Their reports qualify individual workflows. They do not provide a single record of every reachable scene or the presentation states still needing review.

Before this inventory, the remaining visual findings and feature gates were spread across those reports. After it, the final UI pass has an explicit route through the current application, with source locations, prior evidence and missing checks. The pass must preserve saved identities, contextual completion, recovery outcomes and per-device preferences.

Retain an empty dataset for empty states. Never alter a real account or production dataset to manufacture a failure.

## Required review and tests

Review each applicable row in ordinary light/dark appearance and Increase Contrast. Then cover maximum Dynamic Type, Reduce Motion/Transparency and VoiceOver on mobile, and keyboard-only operation on Mac. Record actual device/destination, orientation/window width, data state, original capture and finding. A passing native interaction assertion or compiler result does not establish visual readability.

Inspect phone portrait/landscape, regular iPad and compact split widths, and narrow/wide Mac windows. Follow the same selected source/appearance or edited draft through transitions. Check the top toolbar spacing and the bottommost scrollable control while bars, keyboard or Undo are present. Keep list progress and estimates independent of visible filters.

Use existing native UI journeys for interaction and persistence. For a behavior defect, first reproduce it at an already agreed native/Core/provider boundary, retain the failing observation, then apply the smallest correction and rerun the affected journey. A new test boundary requires its own agreement. Do not test padding constants or use screenshot matching as a readability verdict.

## Completion record

For every reviewed row, record the represented states, source epoch, executed assertions, inspected originals, corrections and remaining limitations. Keep Mac automation startup, protected signing, physical CloudKit/account/Share behavior and physical performance separate. Final acceptance requires the complete [ticket 23](https://github.com/dvcol/planner/issues/23) checklist; this source inventory closes none of those gates.
