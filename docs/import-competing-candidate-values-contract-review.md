Status: Q149 A accepted on 23 October 2026. Q147 A and Q148 A have their scoped local Core and native administration checkpoints. The incoming-value projection below has a [first local real-store checkpoint](prototypes/core-native-import-competing-values.md). ## Concrete case

Current Museum X101 has live lifetime B814, Current museum, and current family F890 rooted in closed A811. A separately valid backup represents the same public Item as unknown candidate D813, Other museum, under competing G893. It also contains new Tour277 bound exactly to X/D and independent Rainy day602. Q148 A keeps current B/F and skips Tour under Skip. Before Q149 implementation, ordinary Overwrite rejected the unknown-D source transformation. A shared-family input already representing B could pass review but failed execution on the expanded candidate set. The linked checkpoint retains the original real-store failure and subsequent qualification.

The proposed manual Overwrite treats the incoming values as the user's deliberate replacement of current X/B. It does not admit D or G. This extends the already implemented predecessor-value projection to a valid competing candidate with a shared, currently authorized predecessor.

| Record | Expected manual Overwrite |
| --- | --- |
| Museum X101/B814 | Apply incoming Other museum and represented complete-owner values, retaining B814. |
| Current F890 and known closure/provenance | Preserve the complete current metadata exactly. |
| Unknown D813 and incoming G893 | Do not admit either identity or family. |
| New Tour277 membership to X/D | Bind the explicitly represented, reviewed dependency to X/B. Retain Tour's own identity, rank and contextual state. |
| Omitted current List referencing X/B | Preserve its complete membership identity, lifetime, rank, completion and history. Live Item content changes normally. |
| Independent Rainy day602 | Import once with its represented data. |

Repeat with D816 in the competing family G893. Also cover an incoming F890 carrying known B814/operation994 and additional D. That shared-family file must represent its own smallest candidate: D813 when D sorts first, but B814 when D816 sorts after B. In the latter case incoming values are already carried by B while Tour still names unknown D816. Both value projection and the separately reviewed D-dependent binding must preserve current B/F without admitting the extra candidate. Results must be independent of which candidate would win if admitted.

## Authorization and limits

Use the existing `applyImport(backup:mode:restoreDeletedData:)`, review, execute, canonical read/export, recovery and receipt boundaries. Add no public type, format, schema, package, target, test hook or agent-administration command.

Apply only in explicit Overwrite, to a source present in the incoming file and matched by exact kind/public ID to a current live source. The incoming source must belong to a separately valid restoration family rooted in a predecessor authorized by the current retained lineage. The shared predecessor closure and every shared known candidate/family provenance entry must agree. Public identity or name alone grants no authority. Unrelated lifetimes, absent lineage and contradictory known provenance retain whole-action rejection.

Do not admit additional incoming deletion authority for the retained owner. An incoming closure that would newly close current B, an incompatible closed family or another unreviewed lineage transformation remains rejected. Preserve current complete family/closure metadata for the value-replaced owner. Independent eligible owners keep their existing selection rules.

Project exact incoming owner/dependency bindings only where the owner is explicitly selected under this reviewed authority. An omitted unknown D cannot become a generally valid external dependency. Skip retains Q148 A unchanged. Keep the original decoded backup immutable and bind review to input, mode, authorization, dataset and current graph.

Reuse whole-owner replacement and exact owned-reference rules. Preserve omitted owners' complete data. Closed reference identities require separate restoration authorization and fresh lifetimes; live incompatible identity/endpoints and retained alias/change collisions reject the whole action. Contextual histories retain exact authorized bindings and observed-change identities. No generic source-identity fallback replaces an appearance.

## Observable review and qualification

Preview reports the current X/B in replacements, with B in both before/after summaries, original paths, complete owned-reference impact and resolved new-owner dependencies. It reports no new source restoration merely for D. Apply returns actual saved B and any genuinely restored reference lifetimes. Do not claim incoming family adoption or synchronization convergence.

First retain the failing literal current-B versus unknown-D workflow through the already approved public real-store boundary. Prove full expected exports, omitted-owner scope, independent import, canonical reads, complete current family retention, recovery, reopen, exact replay and duplicate-free reimport. Extend both candidate orderings/family-ID cases through all five source kinds and owned/contextual reference forms. Preserve no-authority, contradictory provenance, omitted-D, stale-review, precommit and truthful incomplete-recovery outcomes. Reuse native file review/apply/export qualification. No additional direct test boundary is proposed.

Automatic synchronization/consolidation remains a separate requirement. This proposal copies deliberately selected manual backup values onto a current live owner without adopting the backup's competing lifetime.
