# Native Planner implementation map

Planner is a personal native iPhone, iPad and Mac app using Xcode, SwiftUI and shared Core interfaces. Platform layouts must feel native. Quality and stability take priority over schedule; there is no deadline. Apple Calendar export remains outside this map.

This map remains open. Signing is deferred, and it is not the only remaining gate. The [decision register](open-decisions.md) distinguishes accepted behavior, current implementation and executed evidence. An accepted choice, successful build or isolated test does not close a broader requirement.

## Decisions and external actions needed

- **Q127, Mac Calendar presentation.** Narrowing the current inspector aborts Planner with a constraint-update exception. The reviewed alternatives are a hideable native Mac split pane, recommended, or a native sheet. The user has not chosen; failed placement/size/toolbar experiments are reverted. The iPad inspector stays unchanged. [Diagnosis and alternatives](https://github.com/dvcol/planner/blob/dc8c1789/docs/prototypes/native-calendar-mac-inspector-resize.md).
- **Q128, older-backup Overwrite.** A closed predecessor and the current restored record share a public identity but have different lifetimes. The proposed choice deliberately applies represented older values to the current live version, preserving its lifetime and requiring separate authorization for closed owned data. A fresh restored version and rejecting that Overwrite are alternatives. The user has not answered; the old-predecessor guard remains. [Concrete question and impacts](https://github.com/dvcol/planner/blob/164d545e/docs/native-import-live-overwrite-decision.md).
- **Q129, Skip and newly delivered restorations.** Manual Skip preserves the current owner, while restoration convergence selects a deterministic candidate. Their interaction is not settled when a backup introduces a candidate unknown to the current family. The concrete choices are preserve current and skip dependent plans, recommended, consolidate and allow the winner to change current data, or reject the whole import. The user has not answered. [Worked example and required tests](https://github.com/dvcol/planner/blob/1538b740/docs/native-import-new-candidate-skip-decision.md).
- **Q130, concrete Core change stream.** A21/Q33 accept the capability; the executable declaration, future-only/coalescing delivery and native Swift cancellation/reference lifetime now have a concrete review. The user has not answered. Independent local data/recovery observation and existing native refresh integration follow that review; no additional public test injection is proposed. [Contract and required evidence](https://github.com/dvcol/planner/blob/42796062/docs/core-change-stream-contract-review.md).
- **Current Mac UI validation and running build.** Recent Schedule/List-title requests provide no confirmed case results during runner startup. The latest isolated 360-second title attempt reaches the runner after a test-service timeout but leaves an incomplete result bundle, with no fresh title captures or passing credit. All four header production files still match the previously verified correction. A live image comparison proves the open app has an older library loaded than its current on-disk bundle; path-only freshness checks were insufficient. The user is asked to save, fully quit and open the isolated build. The empty/selected-title discrepancy remains open pending that exact comparison. This is neither a new layout pass nor evidence of a signing cause. Do not repeat unchanged startup attempts while current-build feedback is pending. [Runtime diagnosis](https://github.com/dvcol/planner/blob/4d03fbff/docs/prototypes/native-xctest-runtime-diagnosis.md#mac-automation-and-item-startup-follow-up-22-october-2026), [isolated comparison](prototypes/native-list-pane-header.md#isolated-current-build-comparison-retry).
- **Signing and physical access.** Account/team setup remains deferred. Q100 B requires actual signed protected storage before native Agent Control. Signed shared storage, installed Share, physical CloudKit/account transitions and device performance still need their actual capability/device evidence. Local-only substitutes do not close them.
