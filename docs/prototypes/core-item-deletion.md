# Reviewed Item deletion

Context. At baseline `6f9d5e4`, native Category/Tag deletion is qualified, but public Core rejects an Item deletion review as unavailable. An Item can own links and direct Schedules, belong to several Lists, appear repeatedly in Itineraries, and retain separate local completion in each context. Removing its source must remove that entire closure without damaging the surviving plan.

Goal and intended end. Review the complete removal set, require the current session's confirmation token, and commit the Item, its owned data and its references together locally. Retain the other Items, Lists, Itineraries and shared labels. Save minimal deletion metadata and a replayable operation receipt, then independently acknowledge the resulting planner data.

DoR. The accepted contract uses Archive plus confirmed Delete without Trash, deletion of an Item removes its references, and container deletion preserves its sources. Completion follows Q8's global Item precedence and independent local appearances. Repeated itinerary appearances remain independent. Minimal deletion markers, typed review impact, exact operation replay and the public Core/recovery I/O/HTTP test boundaries are already accepted. Calendar and estimate choices are separate pending decisions.

DoD for this Core slice. A reviewed deletion removes every owned link, direct Schedule, List membership, direct Itinerary entry, label association and persisted expanded completion tied to the Item. Surviving owners and their content/state/order remain readable after reopening. A changed dependency set requires a fresh review. Cancellation or rejection leaves the dataset unapplied. Recovery failure before save leaves it unchanged; recovery failure after save reports applied but incomplete and blocks later writes. Exact replay works after the source is gone. MCP continues to prohibit deletion. Qualification and limits are recorded below; native Item Delete presentation is a later slice.

It has two direct appointments and shared Category/Tag associations. The Itinerary owns a separate all-day Schedule. Before deletion, two of five itinerary appearances are Done.

Later admission tests passed against that implementation. Five second-writer cases add a membership, direct entry, Schedule, link or persisted expanded completion after review; every case rejects the old token without mutation. Missing/unknown/foreign-session/changed-command tokens also reject. Reusing an operation for another Item fails. Old completion and membership commands cannot recreate the deleted source. Real configured recovery I/O obstructions qualify the before-save and after-save distinctions. Existing recovery-integrity and authenticated HTTP journeys now cover Item, Category and Tag identities.

The final narrow qualification passed 33 Core functions in 23 suites, 15 iOS 27 simulator Core functions in 10 suites, and three macOS 27 HTTP functions in three suites, with no failures or skips. ## Implementation and remaining gates

Core resolves the full Item closure before saving. Review digests bind source/dependency lifetimes and the exact reference relationships, including expanded completion pairs. Existing Category/Tag digest bytes remain unchanged. Deletion prepares the independent backup, explicitly removes the records because native relationships use nullification, and saves the receipt and markers in one local transaction. A native save error rolls the context back. Recovery publication distinguishes complete from applied but incomplete.

Markers close the Item and its direct Schedule, membership, direct entry and label-association lifetimes. Owned links close with their Item; expanded completion contexts close with their membership. Markers retain identities and deletion metadata, without the deleted Item's title, notes or other content. Recovery validation rejects a live source closed by a marker. No persisted fields, schema migration, portable version or MCP permission changes are introduced. Schema 14 and portable format 1 remain localOnly.

Native Item Delete controls, controlled native save-failure injection, nonempty restoration families, import/restore, recovery repair and List/Itinerary source deletion remain open. The local transaction and markers do not prove physical iCloud conflict convergence or deletion winning over a returning offline device. Mac native UI runtime, signed sync/account/Share tests and whole-app polish retain their gates. The HTTP host emitted macOS autoShortcut connection diagnostics; compilation also reported an unchanged AllDayScheduleTests redundant-require warning and metadata extraction diagnostics. Their resolution is not claimed here. Calendar modes/navigation and itinerary estimates still await Q59-Q61; Calendar export remains outside the map.
