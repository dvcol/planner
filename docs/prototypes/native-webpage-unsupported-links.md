# Native unsupported webpage links

## Accepted scope and required /tdd

Q140 leaves unknown, executable and file URL schemes unsupported. Q145 separately asks how supported Mail/Phone/Maps links should open. This slice changes only unsupported navigation; it does not decide Q145 or disable ordinary website JavaScript.

Use the existing native UI and real loopback HTTP seams. First save a link-policy guide, then select a custom scheme with no fixture handler. Require a native Link unavailable explanation naming the target and offering Keep reading, without an external-opening action. Keeping the guide must preserve its useful HTTP navigation and exact saved bookmark. No new direct test boundary, production hook, package or target is proposed. File and executable navigation follow as actual separate supported-boundary investigations rather than assumed coverage from the custom scheme.

## Definition of done and limits

Observe the focused phone failure before implementation, then pass the unchanged journey on phone and dark iPad with matching Mac compilation and affected failure/content regressions. Inspect original native captures and reconcile source/product hashes before further edits. This qualifies the represented unsupported URL and reader context, not supported-app routing, actual system handoff, every website's scripts, Mac UI or physical acceptance.
