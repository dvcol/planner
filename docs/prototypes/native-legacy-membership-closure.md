# Exact legacy membership closure admission

Q154 and Q155 preserve old deletion markers as original-identity protection without inventing a strict Item/List removal barrier. A delayed physical copy of an exactly closed membership previously made an otherwise valid List unavailable. The same problem affected a sole late copy and detached expanded-completion rows.

Canonical maintenance now excludes memberships whose exact identity/lifetime is already closed, together with their expanded rows. It preserves an independent current membership's identity, rank, local completion and repeated itinerary branches. Retained aliases, explicit completion history, source content and timestamps stay unchanged. A known closed restoration family supplies the existing closure authority for its candidates; this does not adopt or choose an open competing family.

The admission probe detects even a sole closed copy. Without strict removal history it fetches membership markers only; existing strict-removal validation retains its full marker read. Its sparse graph answers only whether an identity is closed. Complete graph and binding validation still precede durable preparation and native save. Unresolved expanded rows enter the existing isolated staging path before missing-root inspection attempts a complete snapshot.

An ordinary Add afterwards creates a new Todo membership. Old deleted or retired-alias actions cannot target that new relationship or change global Item completion. Redelivery preserves the exact current export; original command replay retains its original result and checkpoint. No legacy marker becomes a pair-wide barrier and no observed-removal set is invented.

This uses the approved public Core, real native-input and recovery-filesystem seams. There is no public interface, schema, model, portable format, package, target or production test-hook change. The completion winner, initial-seed algorithm and canonical staging are unchanged.

## Remaining scope

An unclosed legacy alias pointing to a closed root still needs its own admission policy; an old marker supplies no retroactive pair-wide causal authority. Broader source/entry lifetime reconciliation, open competing families, independent expanded-context closure, other prepared commands, alias-specific native/HTTP journeys and further interruption/failure cases remain open.

Actual Mac UI, protected signed/shared storage, installed Share, CloudKit convergence, physical performance, system invocation and final whole-app visual acceptance retain their separate gates. Signing stays deferred.
