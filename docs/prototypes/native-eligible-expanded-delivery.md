# Eligible completion delivery after membership consolidation

Q155 A retains the completion history of memberships retired by duplicate consolidation. A later native expanded-completion row can still reference that exact retired membership. The previous retirement path required a strict removal proving the old generation ineligible, so it rejected a valid eligible contribution even when its alias, source pair, generation and itinerary branch were known.

The existing maintenance path now handles eligible contributions separately from strictly retired generations. Complete stored context identities must identify an actual surviving List entry and its exact List lifetime. A live membership supplies its real binding; a physically retired membership also needs an existing eligible alias to the canonical membership, with the same pair and observed-removal basis. Missing authority does not create a membership or redirect into an ordinary re-add. Non-nil native relationship pointers must agree with the stored identities; contradictions stay unavailable.

The current branch's initial contribution is retained before independently delivered values are added under the existing stable seed identities. Both original Todo and incoming Done survive; the incoming seed cannot make the earlier row look already represented. Contributions join only their exact expanded branch. The existing history winner still gives explicit completion changes precedence, including an explicit Reopen made while the branch was already Todo. Standalone completion, other repeated branches, direct stops, global state, source content, timestamps, order and explicit-change identities remain unchanged. Repeated delivery preserves the exact portable graph.

The isolated context stages unresolved input before building the complete candidate. All binding/history checks and complete graph validation precede durable preparation and native save. Failed validation or preparation rolls back the staged changes. A live baseline may retain implicit empty provenance; the repair does not manufacture explicit observations. Unchanged reads write no maintenance checkpoint.

The change uses existing Core interfaces and the approved native-input/public-observation and recovery-filesystem test seams. It adds no public API, model, schema, portable format, package, target or production test hook. The existing normalization winner, seed algorithm, canonical staging and command replay interfaces are unchanged. The additional checks run only after native admission already requires maintenance; they make no physical-performance or bounded-memory claim.

## Local qualification

The positive tracer contains sixteen cases. Four input forms—an eligible retired membership, a live membership with its relationship missing, a missing List-entry relationship, and a baseline without explicit provenance—each run with or without explicit Reopen and with successful or obstructed recovery preparation. Public queries, exact appearance reads, replay, exports, recovery inspection and fresh bootstrap establish behavior. Repeated input and unchanged reads are tested separately from one another.

Three negative cases retain missing alias authority, a conflicting native relationship pointer, and a changed entry lifetime. They reject the waiting write, leave no reliable operation evidence, preserve recovery bytes and remain unavailable after reopening. Missing alias authority retains the existing invalidInput path at /membershipProvenance/1/membershipId; the other two report readUnavailable.

The [verification](evidence/native-membership-consolidation/eligible-expanded-validation.json) reconciles 263 functions and 864 invocations per platform in ninety suites on Mac and iPhone Simulator. All 809 Core inputs match the 1,150 native inputs. The 514 frozen fixtures, nineteen model sources and earlier test bodies are unchanged. Both affected Swift files pass strict formatting. Matching Mac app, Share and fixture builds and seven existing real HTTP regressions pass. These checks do not qualify actual Mac interaction, installed extensions or system invocation.

The [attempt index](evidence/native-membership-consolidation/eligible-expanded-attempts.json) preserves the actual initial rejection and the later pointer-conflict acceptance before its guard. Review after the first passing cohort identified that visible Done alone did not prove preservation of the original Todo seed. Stronger assertions fail both baseline cases without a prior Reopen; retaining the current contribution before adding the incoming seed fixes those cases. The corrected final cohorts rerun the affected scope. Actual first-epoch product hashes were verified and preserved before rebuilding their directories.

A test-only key-path expression first failed Swift Testing macro compilation and was replaced with an ordinary closure. A preliminary missing-alias assertion expected the wrong error code; inspection established the exact existing validation path, which the final test asserts without changing production error behavior. An early baseline assertion also incorrectly demanded explicit provenance. Q155 permits its empty live binding to remain implicit; the final test instead checks byte-equivalent provenance alongside the other unchanged graph fields. Those failing epochs remain retained.

Only closed, marked disposable stores from passing runs are removed. The [cleanup record](evidence/native-membership-consolidation/eligible-expanded-all-passing-fixture-cleanup.json) records the actual counts and nominal sizes from both epochs. The unchanged authoritative verifier performs the host, database-handle, original-log and ownership checks before deletion; the wrapper avoids repeating its expensive open-file check. Failed inputs and original evidence remain available.

## Remaining scope

Legacy closure without a strict pair barrier, independent expanded-context closure admission, changed owner/entry lifetimes, broader restoration-family reconciliation, other prepared command families, alias-specific native/HTTP journeys and further native-save/interruption faults remain separate work.
