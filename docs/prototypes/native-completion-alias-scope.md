# Fixed appearance scope in completion history

Q155 A keeps repeated itinerary appearances independent. Causal references can all be present while an alias incorrectly points at another itinerary entry or another kind of appearance. Native admission previously accepted that graph when its calculated value happened to match the target's scalar flag. The graph's completion history did not belong to that appearance, even though its references resolved.

The existing shared reference validator now checks appearance kind and fixed itinerary entry identity before calculating states. A direct Item alias retains its public entry identity; an expanded List-item alias retains its List-entry identity. Lifetimes remain subject to the existing restoration-authority rules. List-membership aliases can still have different membership identities, as required for duplicate consolidation; their pair, generation and lifetime rules remain in the graph validator.

This adds one in-memory check to the existing validator, with no additional native fetches. The winner, predecessor traversal, initial seeds, native staging, schemas, portable format and public interfaces are unchanged. It introduces no package, target, test seam or production test hook.

## Remaining scope

This check fixes appearance kind and itinerary entry identity. Membership pair/generation reconciliation, unproven or changed owner/context lifetimes, valid delayed canonical-root delivery and broader restoration-family rules retain their own open work. Repair-specific native-save/interruption faults, alias-specific adapter journeys, actual Mac UI, signed/shared storage, installed Share, CloudKit, physical performance, system invocation and whole-app visual acceptance remain separate gates. Signing stays deferred.
