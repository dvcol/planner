# Restored Item direct-entry rebinding

Q158 A approves the [concrete contract](../native-source-restoration-entry-rebinding-contract-review.md). Source maintenance now admits consistent direct Item entries from independent surviving Itineraries. It rebinds their scalar source lifetime and native Item relationship to the existing deterministic winner, then retires the losing physical Item in the same durable transaction.

## Preserved data and admission

Each entry retains its public identity, lifetime, Itinerary binding, route rank, local Done and complete completion history. The winner retains its own content, global state, archive state and timestamps. The independent Itinerary and unrelated graph remain unchanged. The losing Item's global Done does not become a stop's local Done.

Other losing owned/inbound relationships remain inadmissible. Missing or mismatched native relationships, invalid owners, missing winners and invalid completion history reject before preparation. Core uses one source-maintenance plan for both nonmutating recovery projection and the subsequent native transaction.

Unreferenced retirement retains rule1. Entry rebinding declares sourceRestorationConsolidation rule2. Writer compatibility advances to22, with physical model19, portable4 and recovery envelope2 unchanged. Main publishes a validated projected baseline and metadata before activating control22. Share waits for main activation. Activation itself creates no retirement receipt.
