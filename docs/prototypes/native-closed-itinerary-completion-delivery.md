# Delayed completion after an itinerary stop is removed

A delayed native expanded-completion row could make a surviving itinerary unreadable after its original List stop was removed. The row retained the removed stop's exact public identity and lifetime, but cleanup required a live stop before considering its deletion marker. Public query returned `readUnavailable` with “The unresolved completion has no retained scope binding.”

The shared maintenance staging path now checks retained closure authority before requiring a live stop. It rejects contradictory native relationships and requires an existing or retained membership binding. If the exact stop still exists, its List must match that binding, including when the membership is closed. An exact closed stop or completion can then retire the stale row without transferring its Done value to another appearance. The sparse closure check does not validate the whole dataset; complete snapshot validation still precedes durable preparation and native save. Failure rolls the isolated context back.

Undo can restore the same public stop under a fresh lifetime. A completion from its removed lifetime remains historical and cannot change the restored stop. The other repeated List stop, direct Item appearance, standalone membership, source content, timestamps, route order and retained history keep their current values. There is no new removal barrier, lifetime inference, public API, schema, portable format, package, target or test seam.
