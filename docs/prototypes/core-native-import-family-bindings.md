# Import references to known restoration candidates

## Context and starting state

The accepted portable contract permits references between candidate lifetimes in one open restoration family. Its stable initial winner supplies the live record. References to the closed predecessor do not redirect, and deleting the family closes every candidate. Public identities alone cannot establish that authorization.

At `c73a9bed`, the graph validator already recognizes those candidate bindings, but dataset-bound import review requires every external source reference to have exactly the live lifetime. This can reject a new independent plan referencing another candidate of a fully known, open family. This slice must establish the actual failure through public decode, review and execution before changing that check.

## Goal and end state

Admit an external reference authorized by the current dataset's complete open family, retain the existing live source and family, and save the complete new owner. Resolve the dependency to its current live lifetime in the reviewed/applied graph, retaining the association's own identity, lifetime, order and local state. The immutable input, original paths and operation fingerprint remain unchanged. Obsolete predecessors, unrelated lifetimes and closed families remain protected. Incoming family consolidation and old-predecessor Overwrite stay on the overall map; this slice does not decide their behavior.

## Definition of ready

- A20 and the portable contract's candidate-to-candidate reference rule are accepted.
- Current Skip/Overwrite, complete-owner preservation, explicit restoration and deletion precedence remain unchanged.
- Use the approved public Core decode, review, execute, query/export, recovery and replay seams with real disposable storage. No new interface, test seam, target or package is required.
- The current dataset must already contain the full authorizing family. Incoming metadata cannot grant itself authorization to redirect a predecessor.

## Definition of done and required /tdd

- Seed a valid public backup with two authorized candidate lifetimes and the stable live winner. Review a separate new owner whose only external source reference names the other candidate.
- Reproduce any actual rejection, then admit only the settled authorized case. Preview changes no saved data. Execution retains the source content/lifetime, closure and family while adding the complete owner/reference once.
- Verify acknowledged recovery, reopen, exact replay, idempotent reimport and actual public plan reads. Exercise both import modes where their behavior is the same.
- Reject predecessor and unrelated external lifetimes at useful paths. Deleting the family must prevent a late candidate reference from reviving the source or silently shortening its dependent owner; eligible independent records retain their accepted treatment.
- Run affected import/lineage tests, platform compilation and strict affected lint. Record actual failures and executed outcomes. Physical convergence, native import presentation and the final whole-app review remain separate gates.
