# Delayed canonical membership references

Q155 A requires duplicate memberships to converge while preserving their independent completion history. After an initial consolidation, a later smaller membership can become canonical. An older valid alias may then arrive pointing at the retired larger membership. Only one physical membership remains, so the old duplicate-count check did not run maintenance. Current reads or exports failed even though the retained pair, generation and completion history were sufficient to resolve the reference.

The existing maintenance path now detects that case for a single surviving membership. It requires the same proven Item/List pair and observed removal generation, preserves closed history, and uses the available smaller public membership identity. A declared smaller canonical membership that has not physically arrived remains unavailable until it arrives. Another lifetime of the same public identity stays under existing restoration-family authority; this UUID-resolution check does not reconcile that family itself.

Only affected completion scopes are normalized. An independent itinerary List branch retains its existing implicit Todo state without acquiring an unnecessary alias or expanded-completion row. The existing winner, predecessor traversal, initial seed generation and native staging are unchanged. Ordinary self-canonical history needs no additional source snapshot. A potential missing-root case uses the existing complete graph to check closure authority before maintenance; this is not a bounded-memory or measured-performance claim.

There is no public API, schema, portable format, package, target, test boundary or production test-hook change. Native fixture access supplies independent persisted inputs; public Planner queries, appearance reads, commands, operation evidence, recovery inspection, export and fresh bootstrap establish the outcomes.

## Qualification

The existing smaller-canonical tracer now has seven cases: its original baseline; delayed standalone, first-branch, second-branch and combined aliases; an independent new branch; and a real recovery preparation-write obstruction. It checks exact completion scope, manual rank, shared content and timestamps, byte-identical exports, historical command replay, invalidated query generations and durable reopen. Failed preparation publishes no checkpoint or successful operation and leaves recovery files unchanged; retry converges after filesystem access returns.

Three additional public-interface tests cover a genuinely missing smaller membership, a closed legacy alias alongside an independent live membership, and an already valid same-public-identity restoration family. The first keeps reads and a waiting new write unavailable without changing recovery, then converges to the other writer's exact export when its physical membership arrives. The latter two preserve valid current reads and recovery bytes without publishing unnecessary maintenance.

The verification reconciles 261 functions and 845 invocations per platform in ninety suites on Mac and iPhone Simulator. The 809 Core inputs match the 1,150 native inputs. All 514 frozen fixtures and nineteen model sources are unchanged, as are the original tracer assertions and other preceding test bodies. The three affected Swift files pass strict formatting. Matching Mac app, Share and fixture builds and seven existing real HTTP regressions pass. These are local compilation/storage/HTTP checks, not installed extension, Mac UI or system invocation qualification.

The attempt index retains the original failures and subsequent epochs. Four delayed cases fail before the repair. A first repair also adds an unwanted alias and scalar to the independent new branch; retained original recovery evidence identifies those as the only export differences and matches the acknowledged operation receipt. Restricting normalization to affected scopes preserves the original exact-export assertions. A later compatibility test exposes an overbroad same-identity lifetime check; restricting UUID resolution to different public membership identities preserves that valid family. An intermediate test compiler failure is also retained: comparing non-Equatable completion-change values was replaced with comparison of their public exported JSON, without changing the production type.

Only closed, marked disposable fixtures from passing attempts are removed through the existing verifier. The cleanup record records counts and nominal sizes. Failed inputs, raw logs, source manifests and original recovery evidence remain retained. The first final epoch's actual product hashes were verified and preserved before the compatibility follow-up rebuilt those product directories.
