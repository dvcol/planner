# Fresh local restoration from incoming restored values

Status: Q151 A and Q152 A are accepted on 23 October 2026. This concrete contract is approved for implementation through the existing interfaces and test boundaries. Signing remains deferred; independent native qualification continues.

## Existing interfaces and authority

Keep `applyImport(backup:mode:restoreDeletedData:)`, its review/result types and the existing backup format. Use the approved decode, review, execute, canonical read/export, recovery, reopen and exact replay boundaries. No new public interface, schema, package, target, agent administration action or test hook is proposed.

This transformation requires a represented source X/D, no current live X, explicit Overwrite and restoration authorization. Its independently valid incoming restoration family must establish D beneath a source predecessor authorized by current retained closure/history. Matching public identity alone grants no authority. Shared known predecessor, candidate-operation and deletion provenance must agree before projection; reject contradictions without changing anything.

Project the selected incoming source D onto that authorized closed current source anchor, then use the existing local restoration allocator. Preserve the decoded input. Bind review to the exact original file, current graph, mode, authorization and dataset. Do not make D generally resolvable or weaken generic reference/family gates.

The same source rule applies to Item, List, Itinerary, Category and Tag. Each selected source and required dependency needs its own authorization. Omitted sources and external bindings obtain no authority from another restored source.

## Lineage and source values

Copy the complete represented source fields, including content, timestamps, flags, provenance and applicable manual estimate, under public X and a fresh local lifetime R. R differs from D and every retained lifetime of X. Allocate R during execute, not preview.

Preserve complete current deletion/restoration history. Follow the existing canonical candidate traversal through closed current families to the terminal retained predecessor. For current closed A → B → C, create the new local family rooted at C with candidate R and the executing operation ID. Do not create another branch at A or root it in incoming D.

Exclude the selected source's incoming restoration-candidate authority before family union. The incoming D/candidate operation never becomes current history through this transformation. Local family IDs remain derived from the retained predecessor, so a locally constructed family ID can equal an incoming family ID. That equality does not authorize adopting its candidates or provenance. Unrelated histories retain their existing independent validation/admission rules.

## Preview, saved outcomes and qualification

- Preview remains nonmutating. Report X as a source restoration, with `before: nil`, represented fields, original property paths, required dependencies and separate reference-restoration impact. It is not replacement of a live source and does not promise an already allocated R.
- Applied summaries report actual saved R and Tour's actual rebound dependency. Original-operation replay returns the identical result, identities and checkpoint. Reimporting the same file preserves R and creates no additional family, source or reference.
- Skip keeps deletion and its current dependency-skipping behavior. Without restoration authorization, reject the whole action. Authorization, payload or mode changes require a new review; independent saves invalidate stale review.
- Preserve faithful empty-planner import, which can retain incoming D/family normally. Q147/Q149 current-live value copying and known-family resolution keep their separate accepted behavior.
- Retain the existing failing no-live restored-candidate workflow before the first implementation. Extend in vertical slices through the literal graph, deeper current lineage, five source kinds, represented owned/contextual data and rejection guards.
- Exercise genuine precommit obstruction, applied-but-recovery-incomplete, repair, reopen, exact replay and repeated import through real storage. Verify full exports and recovery snapshots, not only titles or counts. Never report an applied recovery failure as unapplied.
- Run affected strict Swift lint and Mac/iOS qualification, followed by native manual preview/apply/export/relaunch. Actual Mac interaction, signed storage and physical convergence remain separate gates.

This contract does not authorize general incoming-family consolidation, foreign owned-candidate adoption, extra incoming deletion authority, automatic source resurrection or backup administration by agents.
