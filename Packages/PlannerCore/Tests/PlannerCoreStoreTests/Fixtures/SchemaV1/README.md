# V1 migration fixture

This disposable dataset was generated through the public Planner facade at commit `66010bf`, before the owned-link schema existed. It contains one Hotel with Original notes, independently supplied Meeting point A at 35/139, and a 120-minute estimate. Global Complete and Archive produce acknowledged checkpoints 2 and 3. `manifest.json` records the original public identity, dates, field hashes and creation receipt.

`Producer.swift.txt` is the executed generator source. To reproduce a fresh fixture, archive `Packages/PlannerCore` from that commit into a temporary checkout, create a temporary Swift executable package depending on its PlannerCore product, and run the producer with an empty output directory argument. Its Item and dataset identities are intentionally generated by Core. Update the manifest and complete directory together; do not substitute hand-written model records.

The SQLite file and its WAL/SHM companions are copied only after the generator exits. Control and recovery files preserve the old version's real bootstrap and acknowledgement history. Tests copy the entire fixture into a disposable directory before opening it through the current facade. They do not inspect database tables or initialize the old schema using current model classes.

Both SwiftPM and the native Xcode test target copy Fixtures as a directory resource. The native test uses its own test bundle; SwiftPM uses its generated resource bundle. This is local native migration evidence. It does not prove CloudKit schema deployment, a real Share extension, skipped-version upgrades or interruption during migration.
